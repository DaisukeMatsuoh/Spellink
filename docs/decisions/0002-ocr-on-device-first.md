# 0002. 手書きのテキスト化は端末内認識を第一にする

- 状態: Accepted（実機で確認 2026-11-01〜11-07）
- 日付: 2026-10-30

## 背景
選択肢は ①`PluginCommAPI.recognizeElements`（ファーム内蔵認識）②`generateLassoPreview` の PNG を Claude Vision に送る
③`Stroke.recognPoints`（時系列点列）を外部のベクタ手書き認識サービスに送る。

## 決定（案）
①の認識テキストを送るのを基本とし、②の PNG を併送するかは計測して決める。③は SaaS 化の候補として保留。

## 理由
- ①はオフライン・無料・速い。送るのはテキストなので通信量が最小。
- 認識誤りは Claude 側で文脈補正できる見込み。図や数式は②で補う。

## 検証項目
- 日本語・英語混在メモでの認識精度、所要時間。
- `size` 引数にはページ全体サイズ（`getPageSize`）を渡す（ラッソ矩形だと失敗するとの報告あり）。

## 追記（2026-11-07）: 実機での確認
- Nomad（Chauvet 3.31.45）で、ラッソの範囲を端末内で認識できる。「今日は何曜日？」などの日本語は正しく読めた。所要時間は 0.7〜2.8 秒（`recognizeElements`、記録は `reports.jsonl` の trace）。
- 文字でないもの（楽譜・絵）では `null` が返る。空として扱い、「文字として読み取れない内容です」を伝える（`docs/spec/ask-flow.md` の E4）。
- 乱れた手書きは、誤って読まれることがある（「1+1=？」が「It 1 = て」になった例）。質問は認識結果を使うので、答えの質は認識に依存する。将来の改善は `docs/notes/research/2026-11-02-non-text-input.md`。
