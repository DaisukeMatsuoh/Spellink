# 0003. 回答は単線フォント由来のストロークとしてページに書き込む

- 状態: Proposed（合成ストロークの挿入可否と速度を実機で確認後に Accepted へ）
- 日付: 2026-10-30

## 背景
回答を「魔法の紙」のように筆跡として浮かび上がらせたい。先行事例（sn-copilot の PilotChat）はテキストボックスで挿入しており、筆跡化は未開拓。

## 決定（案）
- 単線フォント（日本語: KanjiVG、英数字: Hershey）のグリフパスをポリライン化し、微小なゆらぎと筆圧を付けて
  `createElement(TYPE_STROKE)` → 点列・筆圧を書き込み → `insertPageElements` でページに挿入する。
- 配置はラッソ矩形の直下から。ページ幅で折り返し、溢れたら次ページを追加。
- Claude のストリーミング応答に合わせて **1 行ずつ** 挿入し、書かれていく様子を見せる。
- 挿入できない場合のフォールバックは `insertText`（テキストボックス）。

## 理由
- 筆跡としてノートに残れば、純正機能（ラッソ移動・コピー・消しゴム・検索用認識）がそのまま効く。
- 行単位挿入で e-ink のリフレッシュ回数を抑えつつ、演出も得られる。

## リスク
- 1,000 ストローク超で JS↔ネイティブ往復が遅い可能性 → ストローク生成を Java TurboModule に移す。
- KanjiVG は CC BY-SA 3.0。配布物への帰属表示が必要で、データ改変物には継承義務。商用化時に再検討。

## 追記（2026-10-31）: 筆跡生成はブリッジ側で行う
- グリフデータ（KanjiVG + Hershey、約 13MB）とレイアウト・筆跡化はブリッジ（PC）側に置き、プラグインには
  ページ座標のストローク（点列と筆圧）だけを送る。プラグインは軽いまま、言語追加もブリッジ側だけで済む。
- KanjiVG はセットアップ時にダウンロードして生成する（リポジトリには含めない）。生成物は CC BY-SA 3.0 のまま。
- 実装: `bridge/internal/ink/`（当初 TypeScript、ADR 0008 で Go に移植）。行が確定するたびに `line` メッセージで送り、プラグインは 1 行 = 1 回の `insertPageElements` で挿入。
- 計測（ROCK 5B+）: 1 行（19 ストローク）≒ 6.9KB の JSON。300 字の回答で数百 KB 程度の見込み。LAN なら問題ないが、必要なら差分符号化で圧縮する。
- 点列の書き込みは SDK 実装上、`add` だと 1 点ごとにネイティブ呼び出しになる。`setRange` で一括書き込みできるかを初回に試し（`probeFillMode`）、実機で速度を測る。
