# 0005. 自宅機で公式 Claude Code を動かす「ブリッジ」経由で Claude を使う

- 状態: Accepted（0004 を置き換え）
- 日付: 2026-10-30

## 背景
ユーザーは API キー（従量課金）ではなく、手持ちの Claude サブスクリプション（Zed などから Claude Code を使っているのと同じ形）で使いたい。

Anthropic の規約（https://code.claude.com/docs/en/legal-and-compliance 、2026-10-30 時点の記載）:
- サブスクリプションの OAuth は **Claude Code と Anthropic 純正アプリでの通常利用** 向け。
- サードパーティ開発者は、自分のアプリに Claude.ai ログインを組み込むこと、ユーザーの代わりに Free/Pro/Max の認証情報でリクエストを流すこと、
  **Claude.ai の認証情報やセッショントークンを収集・保存・中継すること** が禁止されている。サインインは Anthropic 自身のフローで完了しなければならない。
- 一方で「エンドユーザーが **改変していない Claude Code バイナリ** に自分のサブスクリプションでサインインすること」は妨げない（ホスト環境上で動かす場合も含む）。
- 2026-01 からサーバ側でのブロック、2026-04-04 からサードパーティツール経由はサブスクリプション対象外、と報じられている。

→ **プラグインにアカウント/パスワード入力を持たせる案、トークンを抜き出して直接 API を叩く案は規約違反なので採らない。**
（Zed は Claude Code 本体を起動して ACP でつないでいる＝この「改変していない Claude Code を動かす」側に当たる。）

## 決定
```
Supernote（プラグイン）──HTTP(S)──▶ ブリッジ（ユーザー自身の常時稼働機。開発時は ROCK 5B+）
                                         └─ 公式 claude CLI を -p（ヘッドレス）で起動
                                            ※ユーザーが Anthropic 純正フローでログイン済み
```
- ブリッジは小さな Node の HTTP サーバ。`POST /ask`（認識テキスト・任意でラッソ PNG・言語）を受け、
  `claude -p --output-format stream-json`（ツールは無効化、回答用システムプロンプトを付与）を実行し、テキストを逐次プラグインへ返す。
  - `--bare` は使わない（ヘルプ記載の通り、bare モードの認証は API キーのみになる）。
  - CLI の起動待ちが気になれば、`--input-format stream-json` で常駐プロセスを温めておく方式を検討。
- プラグイン⇔ブリッジ間の認証は **ブリッジが発行するペアリング用トークン**（Anthropic の認証情報とは無関係）。初回に `MyStyle/` の設定ファイル等で受け渡す。
- 到達経路: まずは自宅 LAN。外出先対応は Tailscale / Cloudflare Tunnel 等を後で検討（そのとき TLS 必須）。
- **API キーモードも残す**（ブリッジを置けないユーザー向け、プラグインから直接 Anthropic API）。設計上はプラグインから見た「回答ストリームの供給元」を差し替えられるようにしておく。

## 追記（2026-10-30）: 対応 OS・複数ブリッジ
- ブリッジは **macOS / Linux / Windows** 向けに配布する（Node 製の単一プログラム。自宅は ROCK 5B+、職場は Mac、のように複数台を想定）。
- 利用条件は「**同じネットワークに、Claude Code にログイン済みの PC があること**」。VPN は前提にしない（上級者向けの任意オプション）。
- 接続先の切り替えは SSID ではなく「**ペアリング済みブリッジを全部同時に試し、最初に正しく応答したものを使う**」方式にする。
  - Android で SSID を読むには位置情報権限が要り、プラグインからは取れない可能性が高い。並列プローブなら SSID 不要で、ネイティブコードも不要。
  - IP が DHCP で変わる問題は、mDNS（`_cloute._tcp`）での発見か `.local` 名の解決で補う（要実機確認）。
- バックエンドは Claude Code 以外（Codex の `codex exec` など）も差し替えられるようにしておく。
- 職場で使う場合の注意: 社内 Wi-Fi は端末間通信を遮断している（AP アイソレーション）ことが多い。業務メモを個人サブスクに送ることの社内規定も要確認。
- Mac がスリープするとブリッジに届かない → ブリッジ側でスリープ抑止オプション（`caffeinate` 等）を用意する。

## 理由
- 規約に沿ってサブスクリプションを使える唯一の現実的な形。
- 認識テキストは数百バイトなので、往復が 1 段増えても通信コストは小さい。
- ブリッジ側で将来の機能（ベクタ OCR、筆跡スタイル生成、会話履歴）を増やせる。

## 結果・注意
- 自宅に常時稼働機が必要（ユーザーは ROCK 5B+ を保有）。外出先で使うにはトンネルが要る。
- 配布するなら「各ユーザーが自分の機械で、自分のアカウントで Claude Code にログインする」ことを手順の前提にする。
  ブリッジが他人の利用を中継する（＝ホスティングして他ユーザーに使わせる）形は不可。SaaS 化するなら API キー（従量）ベースで別設計。
- 製品名・ロゴに「Claude Code」「Anthropic」を使わない（「Claude Code で動作」と平文で書くのは可）。
- Pro/Max の利用上限は「通常の個人利用」が前提。
