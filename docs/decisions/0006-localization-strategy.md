# 0006. UI と筆跡出力のローカライズ方針

- 状態: Proposed
- 日付: 2026-10-30

## 背景
メインは日本語、英語も同等に扱いたい。将来は中国語・スペイン語・韓国語なども。
ローカライズは2層ある: (1) ボタン名・メッセージなどの UI 文字列、(2) **回答を筆跡にするための単線グリフデータ**（文字体系ごとに別データが要る）。
(1) は SDK に言語変更リスナー（`registerLangListener`）があり、ボタン名もローカライズ可能なので安い。(2) が本当のコスト。

## 決定（案）
- UI 文字列は最初から ja / en のメッセージカタログで持つ（ハードコード禁止）。
- 筆跡データは文字体系単位で追加する:
  | 言語 | 候補データ | ライセンス |
  |---|---|---|
  | 日本語（かな・漢字） | KanjiVG | CC BY-SA 3.0 |
  | 英語・ラテン文字 | Hershey 系単線フォント（アクセント記号付きが必要なら OFL の単線フォントを検討） | ほぼ自由 / OFL |
  | 中国語（簡体・繁体） | Make Me a Hanzi（筆順の中心線データ） | Arphic Public License 等（要確認） |
  | 韓国語 | 字母（ジャモ）の単線データから合成 | 要調査 |
- グリフが無い文字はテキストボックスに切り替える（文字単位ではなく回答単位で切り替え、見た目の混在を避ける）。
- 手書き認識の言語は端末の認識言語設定に従う（プラグイン側では選べない想定。要確認）。

## 次の言語の優先度
Supernote の国別販売データは公開情報で見つからなかった。開発元 Ratta が中国企業で、公式開発者ドキュメントが英語と中国語で出ていることから、
**中国語（簡体/繁体）を次点** とし、スペイン語・ドイツ語・韓国語はユーザーの要望を見て決める。
