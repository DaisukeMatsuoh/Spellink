# 0009. 長い回答は「字数を合わせる」＋「直後に挿入したページへ続ける」

- 状態: Proposed（実機でページ挿入・切り替えが動くか確認後に Accepted）
- 日付: 2026-10-31

## 背景
スパイク版は回答がページの下端に達すると打ち切っていた。NOTE のページは固定サイズで、無限キャンバスはない。
詳細: `docs/notes/research/2026-10-31-page-overflow-and-canvas.md`

## 決定
1. ブリッジは選択範囲の下に入る字数を見積もり、システムプロンプトで回答の長さを指示する（60〜600 字の範囲）。
2. それでも溢れたら、プラグインが元のページの直後に新しいページを挿入し、そのページに切り替えて続きを書く（元のページ＋最大 2 ページ）。
3. 回答は常にページ幅で折り返す（横スクロールなし）。

## 理由
- e-ink では画面のスクロールやパンが遅い。ページめくりは純正の操作で速い。
- 既存の次ページには書かないので、ユーザーの書き込みを壊さない。

## 却下・保留した案
- 無限キャンバス（拡大縮小・パンしながら書ける紙）: プラグインの範囲外。保留。
- 俯瞰ビュー（閲覧のみ）、要約＋リンク: 今後の候補。
