# 0012. 同じノートでの質問は、前のやり取りを踏まえて答える（ブリッジが会話を記憶する）

- 状態: Accepted（実機で確認 2026-11-07。ユーザー「完璧」）
- 日付: 2026-11-07

## 背景
ブリッジは質問ごとに Claude Code を新しく起動する（`claude -p`、`--no-session-persistence`）。過去のやり取りを渡していなかったので、同じノートで続けて書いても「それをもっと簡単に言って」のような続きの質問は通じなかった。手書きノートでの会話では、続きの質問が普通に起きる。

参考: Claude Code 自身の会話（例: Zed 経由）は、`~/.claude/projects/<プロジェクト>/<セッション>.jsonl` に、出来事のたびに追記される。API は会話を覚えておらず、毎回、これまでの会話の全部を送り直す。長くなると、古い部分を要約に置き換える（圧縮）。

## 決定
1. **記憶の単位は、ノート 1 冊。** プラグインがノートのファイルパスを `ask` の `note` に入れて送る。ブリッジは `note` が同じ質問どうしを、同じ会話として扱う。`note` が空、または長すぎる（1024 字超）ときは記憶なし。
2. **会話はブリッジに保存する。** 端末に保存手段がなく、Claude に渡すのもブリッジだから。`<設定ディレクトリ>/history/<note のハッシュ>.jsonl` に、質問（手書きの認識結果）と回答を 1 行 1 往復で追記する。ファイル名は note キーのハッシュで、端末側のパスをこの機械のパスにしない。
3. **全部残し、渡す量だけを制限する。** 質問のたびに、新しいほうから「質問＋回答の合計が `history.contextChars` 字（既定 8000）に収まる分」を、古い順に並べて質問の前に付けて渡す。往復数では決めない（1 往復の長さがまちまちなため）。1 往復を途中で切らない。
4. **Claude Code のセッション再開（`--resume`）は使わない。** 毎回こちらで文面を組み立てて渡す（`history.Transcript`）。渡す内容と量を制御でき、ブリッジを再起動しても続き、Claude Code の保存形式に依存しないため。
5. 失敗・キャンセルした質問は記憶しない。字数を超えて途中で止めた回答は、受け取った分を記憶する。
6. **圧縮の考え方を設定に入れる（実装は未）。** `config.json` の `history.compaction` は、`contextChars` を超えた古い会話をどうするかを表す。今は `"none"`（送らないだけ。ファイルには残る）のみ。`"summarize"`（古い部分を要約して先頭に付ける）は予約で、指定すると、ファイル名つきのエラーで起動を止める（黙って無視しない）。`history.contextChars` を負にすると記憶を切る。
7. 履歴の削除は、設定画面から。「すべての会話を忘れさせる」（`clearHistory`）と、**「このノートの会話を忘れさせる」（`clearHistory` に `note`。2026-11-08）**。後者は、ノートの中から設定を開いたときに使える（開いているノートがなければ、何も送らない）。

## 理由
- 手書きの短いやり取りは 1 往復が小さく、8000 字なら数十往復が入る。必要なら設定で増やせる。
- 渡す量が増えるほど、応答が遅くなり、使用量も増える。そのため、既定は控えめにし、圧縮を後から足せる形にした。
- 履歴は利用者自身のマシンにだけある。中継サーバーや Cloudflare には、暗号化された通信しか見えない（ADR 0007）。

## 結果・注意
- ノートを複製・移動してパスが変わると、別の会話になる。同じパスに別の内容のノートを作ると、前の会話が混ざる（パスを再利用した場合）。
- 手書きの質問は認識誤りを含みうる。記憶するのは認識結果で、Claude は、前の質問の誤認識も含めて読む。
- 履歴ファイルは平文（利用者のホーム下、0600）。必要になれば暗号化を検討する。
- 圧縮（要約）、ノート単位の削除、履歴の閲覧は未実装。

## 却下・保留した案
- 往復数（10 往復など）で区切る: 根拠が弱く、長さが不均一なため却下。
- Claude Code のセッション再開（`--resume`）: 上記 4。
- 端末（プラグイン）に履歴を持たせる: 端末に保存手段がないため不可。
- ページ単位の記憶: 続きの質問は、別のページに書くことも多いので、ノート単位にした。
