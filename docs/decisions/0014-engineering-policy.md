# 0014. 開発ポリシー: 戻り値は必ず確認し、全ケースを表にしてから実装する

- 状態: Accepted（ユーザー指示 2026-11-07。配布するプラグインとアプリの品質基準として、以後すべての変更に適用する）
- 日付: 2026-11-07

## 背景
このプロジェクトは、小さなプラグインとブリッジだが、世に配布する前提で作る。組み込み開発の業界の標準的な作法を、最初から守る。
実機の不具合の調査（ページをまたぐ回答の中断、ページが空に見える現象）で、次の種類の欠陥が、コードの複数の場所に見つかった。

- **戻り値を確認していない。** SDK は `success`（呼び出しが通った）と `result`（実際にできたか）を分けて返す。`result: false`（保存失敗、挿入失敗）を捨てていたので、保存が拒否されても、次のページ挿入に進みえた。
- **ケースを考えていない。** 「連打」「処理中の取消」「別ノートへの移動」「接続の断」「ブリッジの無音」「遅れて届くフレーム」「範囲外・壊れた値」が起きたときの処理が、決まっていなかった（書かれていなかった）。
- **受け渡しの検証がない。** モジュール間・プロセス間で受け取る値を、使う前に確かめていなかった。
- **想定していなかった、という理由の不具合**が、実機で見つかる不具合の大半だった。

## 決定（ポリシー）
### P1. 戻り値は必ず確認する
1. 関数・API・外部プロセス・ファイル・ネットワークの**戻り値は、必ず受け取り、確かめてから使う**。捨てるときは、捨ててよい理由をコメントに書く（例: 表示を動かすだけの呼び出しの拒否）。
2. 確かめるのは、成功か失敗かだけでなく、**値の型・範囲・長さ・個数・欠け・NaN/無限大**まで。
3. 成功を、**結果で**確かめる（ページを挿入したら、ページ数が増えたことを確認する）。「呼び出しが通った」は、「できた」ではない。
4. 例外を握りつぶさない。握りつぶす場合は、記録し、その後の処理を決めてある場合に限る。

### P2. ケースを洗い出し、決めてから実装する
1. 異常系を含む**全ケースを、先に列挙する**。正常系だけを仕様と呼ばない。
2. 各ケースの処理（中断、続行、無視、再試行しない）を、**コードを書く前に決める**。決められないケースは、利用者に確認する。
3. 利用者は、考えもしないタイミングで、考えもしない使い方をする前提で設計する。
4. **場当たり的な再試行・回数や時間で帳尻を合わせる処理を入れない。** 識別は確実な ID・通し番号で行う。

### P3. 状態遷移表を書く（`docs/spec/`）
1. 状態を持つ処理は、**状態遷移表（縦軸=状態、横軸=イベント、セル=処理と遷移先）**を書く。ステートマシン図ではなく、**全マスを埋めるマトリクス**。
2. **起こりえないマスにも、起こりえない理由を書く。** 理由が書けなければ、起こりうるとして処理を決める。
3. **コードを書く前に表を直し、確認してから実装する。** 表が仕様で、コードとテストは表に従う。
4. 表の各マス（`—` を除く）に、少なくとも 1 つのテストを対応させる。`！`（穴）が残っている機能は、完了と呼ばない。
5. 不具合が出たら、表のどのマスが誤り、または空欄だったかを、記録する。

### P4. 受け渡し（インターフェース）を検証する（`docs/spec/interfaces.md`）
1. **信頼境界（SDK、他プロセス、ネットワーク、ディスク、利用者の入力）から来る値は、受け取る側が必ず検証する。** 型定義は実行時の保証にならない。
2. 検証に通らなかったときの処理を決めて書く。黙って通さない。
3. 「相手が正しく作るはず」を理由に省かない。バージョン違い・バグ・壊れたファイル・改ざんは起きる。
4. 境界の一覧は台帳に書き、未点検の境界を残さない。

### P5. 外部への依頼は 1 本ずつ、終わりまで待つ
1. ノートアプリ（SDK）への依頼は、1 つの列を通し、**前の依頼が終わってから**次を送る。時間切れで見切った依頼も、ホストが終えるまで次を送らない。
2. すべての外部呼び出しに、**時間切れ**を付ける。無応答を、別の失敗（「ノートが閉じられた」など）と取り違えない。
3. 取消・中断が起きても、書いた分は巻き戻さず、状態を利用者に伝える。

## 最初の適用（2026-11-07）
- `sdk.ts`: 依頼の直列化（`native`）、`result: false` の失敗扱い（`callChecked`）、ページ挿入後のページ数の確認、読み取りの逐次化、時間切れを別の失敗と取り違えない、`setLassoBoxState` も共通の処理へ。
- 回帰テスト: `__tests__/sdkSafety.test.ts` ほか。拒否のチェックを外すとテストが落ちることを確認。
- 状態遷移表（`docs/spec/`）の初版を作り、現状の穴を洗い出した。穴の修正は表の優先順に進める。

## 結果・注意
- 状態遷移表は、書くのに時間がかかる。ただし、不具合の調査と手戻りの時間より小さい。
- 表に書いた仕様と実機の動作が違うときは、**表を先に直し**、理由を記録してからコードを直す。
- 実機の戻り値が仕様と違う場合に備え、ブール値の `result` はトレースに記録する。
- 判断が要る項目（❓）は、決めるまで「現状のまま」とし、進捗ファイルに残す。
