# 0017. 家の中の直結のために、名前と証明書の発行を手伝う小さなサービスを運営する

- 状態: Proposed（ユーザーが作ると決定 2026-11-21。設計の確認待ち）
- 日付: 2026-11-21
- 前提: ADR 0011（LAN 直結 wss。利用者の Cloudflare トークンが要るのが課題）、`docs/notes/research/2026-11-20-direct-connection-options.md` §2

## 決定
Spellink が「名前・証明書サービス」（以下 **名前サービス**）を運営し、利用者は何も設定せずに、家の中では端末からブリッジへ**直接** `wss://` でつなげるようにする。通信の中身は名前サービスを通らない。

## 何を、どこに作るか
| 部品 | 置き場所 | 中身 |
|---|---|---|
| 名前サービス本体 | `bridge/internal/lanname`（サーバ側）＋ `spellink-bridge names` サブコマンド（リレーと同じバイナリ） | 小さな HTTPS の API。中継と同じ機械で動かし、`https://names.spellink.uk` で公開（Cloudflare Tunnel）。状態はファイル 1 つ（ID → 公開鍵・IP・最終更新） |
| ブリッジ側の登録クライアント | `bridge/internal/lanname`（クライアント）＋ `internal/lantls` の新しい方式 | 起動時に自分の ID と LAN の IP を登録し、certmagic の DNS-01 の TXT を名前サービス経由で書く（libdns のプロバイダとして実装） |
| 端末 | 変更なし | ペアリングで渡る接続先に `wss://<id>.lan.spellink.uk:8766/v1` が加わるだけ。端末は既存の並列接続で、家では直結、外では中継が勝つ |

## 仕組み
1. **ID**: ブリッジが初回に Ed25519 の鍵を作り（設定ディレクトリ、0600）、公開鍵のハッシュ（16 進 32 桁など）を ID にする。**ID は公開鍵から決まる**ので、アカウントも登録の審査も要らず、他人が同じ ID を名乗れない。
2. **登録** `POST /v1/register {id, publicKey, ip, time, nonce, signature}`: 名前サービスは、署名・時刻（±5 分）・nonce の再使用を確かめ、`<id>.lan.spellink.uk` の A レコードをその IP にする。**IP はプライベートの IPv4 だけ**受け付ける（公開 IP を載せない）。
3. **証明書** `POST /v1/acme {id, value, time, nonce, signature}` / `DELETE`: 名前サービスが `_acme-challenge.<id>.lan.spellink.uk` に TXT を書く（名前サービスがゾーンを持つので、acme-dns の CNAME は不要）。**証明書の秘密鍵は、ブリッジの外に出ない**（名前サービスは TXT を書くだけ）。
4. 名前サービスが触ってよいのは `*.lan.spellink.uk` と `_acme-challenge.*.lan.spellink.uk` だけ。コードで名前を検査し、それ以外は書かない。
5. 守り: 接続元ごとの回数制限、ID あたりの更新頻度の上限、ID の数の上限、ログに IP を残さない（中継と同じ方針）。
6. 失敗しても使えなくならない: 名前サービスが止まっても、取得済みの証明書（90 日）と A レコードはそのまま使える。直結がだめでも、端末は中継で届く。

## ユーザー（運営者）がやること
- Cloudflare で、名前サービス用の API トークンを作る（Zone → DNS → Edit。**`spellink.uk` のゾーンだけ**）。名前サービスの機械にだけ置く。
  - 注意: 無料プランでは `lan.spellink.uk` だけのゾーンは作れないので、トークンは `spellink.uk` 全体を編集できる。`bridge.spellink.uk` などを守るのは名前サービスのコード側の制限になる。より安全にするなら、**名前用に別の安いドメインを取る**（例 `spellink-lan.uk`）案もある。
- `names.spellink.uk` を、中継と同じトンネルに追加する。

## Let's Encrypt の上限（要確認）
- 1 つの登録ドメインあたり、新規の証明書は週 50 枚（更新は別枠）。小規模な公開のうちは足りる。
- 先の調査メモでは「Public Suffix List に `lan.spellink.uk` を載せれば解決」と書いたが、**PSL は Let's Encrypt の上限を避けることだけを目的とした申請を受け付けない方針**と理解している（公開前に PSL の案内を確認する）。上限が問題になったら、Let's Encrypt の「上限の引き上げ申請」を使うのが本筋。

## 結果・注意
- ルーターの DNS リバインディング対策（公開の名前がプライベート IP を返すのを遮断）がある家では、直結が失敗し、中継が使われる。利用者向けの文書に例外設定の方法を書く。
- 名前サービスには、ブリッジの ID と LAN の IP が見える（内容・鍵は見えない）。プライバシーポリシーに追記する。
- ADR 0011（利用者が自分のトークンで行う方式）は、上級者向けの方式として残す。
