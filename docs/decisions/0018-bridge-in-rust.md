# 0018. ブリッジと中継を Rust に移植する（ADR 0008 を置き換える）

- 状態: Accepted（ユーザーが決定 2026-11-21。実装中）
- 日付: 2026-11-21

## 背景
ADR 0008 でブリッジを Go にした。その後、核（グリフ → 行の組み立て → ストローク）だけを Rust で作り、Go と1バイトも違わない出力で比べた（`docs/notes/research/2026-11-21-rust-measurement.md`）。

| | Go | Rust |
|---|---|---|
| 待機時のメモリ | 18〜19 MB | 10 MB |
| 回答を組み立てる間のピーク | 30〜32 MB | 10 MB |
| 1回答の組み立て時間 | 3.8 ms | 0.97 ms |
| バイナリ | 10.7 MB | 0.58 MB |

私（エージェント）は「待機で10MB減っても利用者には分からない」と評価した。ユーザーは、これを退けた。①処理が積み重なれば効く ②利用者が増えたとき、VPS 上の中継では特に効く ③小さく速く、攻撃面が少ない ④物理的に小さいので、依存が多くても脆弱性の面積は小さい ⑤単一バイナリにして、VPS では scratch コンテナに置きたい。

## 決定
1. **ブリッジ（`serve`・`device`・`app`…）と中継（`relay`）の全体を、Rust に移植する。** 仕様（プロトコル、状態遷移表、ファイル形式、設定、台帳、履歴）は変えない。端末（プラグイン）は、何も変えずに動くこと。
2. **非同期の基盤は tokio。** WebSocket は tokio-tungstenite（axum 経由）、Noise は snow（`Noise_NNpsk0_25519_ChaChaPoly_BLAKE2s`、前置き `spellink/2`。Go 版と相互接続できること）、証明書の取得は instant-acme（DNS-01、Cloudflare）。依存は、これらと serde 系・flate2 など、必要なものだけ。サプライチェーン対策として、`Cargo.lock` をコミットし、`cargo audit` と `cargo deny` を CI に置く。
3. **移植は、パッケージごとに、Go のテストを Rust のテストに写し、置き換える。** 表（`docs/spec/` → 生成されるコードの表）は、Rust 側にも生成する（生成器 `plugin` 側の `npm run spec` を、Rust の出力にも対応させる）。Go 版は、**同等になるまで残す**（相互接続の確認に使う: Go のブリッジ ⇄ Rust の中継、Rust のブリッジ ⇄ Go の `check`）。同等になったら、`bridge/` を Rust に置き換える。
4. **VPS の中継は、musl の静的リンクの単一バイナリにして、scratch コンテナに置く。**（ユーザー要望）。
5. 回答の核は、すでに Go と同じ出力であることを、テストで固定している（`experiments/bridge-rs` → 移植先の `bridge-rs/`）。

## 影響
- 開発ツールチェーンが、Go から Rust（edition 2024）に変わる。`CLAUDE.md`・CI・`release.yml`・手順書の Go の記述は、置き換え時に直す。
- 配布物の大きさは約1/10になる見込み。ただし、全体を移植した後の実測（待機のメモリ、バイナリ、起動時間）を、同じ手順で取り直す。
- 移植の途中は、Go と Rust が併存する。**どちらが正かは、`docs/notes/progress/rust-port.md`** に書く。

## 却下した案
- Go のまま（待機で10MB減るだけ、という評価）。ユーザーが退けた。
- 核だけ Rust（cgo や別プロセス）。単一バイナリと scratch の利点を失うので、却下。
