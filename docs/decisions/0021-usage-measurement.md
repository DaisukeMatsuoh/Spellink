# 0021. 使われ方の計測: 中継が時間と件数だけを数え、集計を公開する

- 状態: Accepted（ユーザーが同意、2026-11-22）。実装済み: 手順 1・2・4（国の引き 3 は未実装）
- 日付: 2026-11-22

## 背景
中継は、運営が負担する（ADR 0020）。次に何を良くするかを決めるために、**どこが遅いか・どこに余裕がないか**を、データで見たい。ただし、個人に関わるものは取らない。

## 決定
1. **測るのは、中継の内側だけ。** 端末とブリッジの間は Noise で暗号化されていて、中継には中身が見えない。見えるのは、時間と件数と大きさだけで、それだけを使う。
2. **取るもの（時間の長さと件数のみ。時刻と ID は持たない）:**

   | 名前 | 何か |
   |---|---|
   | `ping_ms{side=client\|bridge}` | 中継が WebSocket の ping を送り、pong が返るまでの時間（端末と中継、ブリッジと中継の間の遅れ。アプリのプロトコルは変えない） |
   | `forward_ms` | 中継がフレームを受けて、相手に書き終えるまでの時間（中継自身の処理の重さ） |
   | `setup_ms` | 端末が来てから、ブリッジが受け入れて、つながるまでの時間 |
   | `session_s` | セッションの長さ |
   | `session_bytes` | セッション 1 つあたりの通信量（幅ごと） |
   | `sessions`、`peak_concurrent` | 始まったセッション数、同時接続の最大 |
   | `refused{reason}` | 断った数（満員、時間切れ、不正など） |

   時間の幅（ミリ秒）: 10、20、50、100、200、500、1000、2000、5000、それ以上。**ヒストグラム（幅ごとの件数）**で持つ。
3. **地域:** 中継が、接続元の IP から**国**だけを引く（ローカルの無料の GeoIP の国データベース）。引いたら IP は**捨てる**（保存も、ログへの記録もしない）。どの中継か（`us.relay`・`jp.relay`）も、地域として使える。
4. **取らないもの:** ID、部屋の名前、IP、端末の種類、ユーザーエージェント、個人ごとの記録、中身、時刻の細かい並び（日単位に丸める）。
5. **小さい集計は出さない。** 件数が 20 未満の（国・日）は、公開の集計に含めない（小さな国で個人が推測されないように）。
6. **公開の形:** 中継が、`GET /v1/stats`（認証なし、集計のみ）で、直近 8 日の日ごとのヒストグラムを JSON で返す。再起動で消えないよう、`/data` に書き出す（0600）。
7. **ダッシュボード:** GitHub Actions が、**週に 1 回**、各中継の `/v1/stats` を取り、ヒストグラムを**足して**（パーセンタイルの平均はとらない）、`docs/usage/usage-dashboard.md` と、元のデータ `docs/usage/data/YYYY-Www.json` をコミットする。p50・p90・p99 を、地域（国と中継）ごとに表にする。VPS にリポジトリへの書き込みの認証情報は置かない。
8. **端末側の測定**（診断画面の往復時間）は、画面に出すだけで、送らない。端末の測定値を集めるのは、Noise の外に出す設計が要るので、やらない（必要になったら別の ADR）。
9. **知らせる:** プライバシーの文書に、何を数えるかを書く（ADR 0020 の「未決」の文書づくりの一部）。

## 見えること、見えないこと
- 見える: 中継が遅くなる時間帯・地域、同時接続の余裕、断っている数。
- 見えない: 家の中の直結（LAN）を使っている割合。中継を通らないため。これは、ブリッジの側が数えて、公開の `/stats` ではなく、別の判断で決める。

## 実装の順序
1. 仕様（`docs/spec/interfaces.md` に `/v1/stats` の I17、ヒストグラムの幅と検証）。
2. 中継の集計（Rust）と、ping の測定。テスト（幅の境界、NaN・負の値、再起動での復元、20 件未満の除外）。
3. GeoIP の国の引き（データベースは、バイナリに入れず、設定で渡す。ない場合は「不明」）。
4. Actions のダッシュボード（実際に動かすには push が要る）。

## 実装の状況（2026-11-22）
- ✅ 仕様: `docs/spec/interfaces.md` の I35（pong）・I36（`stats.json`）・I37（ダッシュボードの入力）。
- ✅ 中継: `bridge/src/stats.rs`（ヒストグラム、日ごと、8 日、保存と復元）、`bridge/src/relay.rs`（ping、転送時間、セッション、断った数、`GET /v1/stats`）。`--data DIR` があれば `DIR/stats.json` に 60 秒ごとと終了時に保存する。
- ✅ 副産物の修正: これまで、ping・pong を受けるたびに「無通信の期限」が延びていた。いまは、データのフレームだけを数える（`tests/relay.rs`）。
- ✅ ダッシュボード: `scripts/usage-dashboard.mjs`（Node のみ・依存なし）、`.github/workflows/usage.yml`（週 1 回）。中継の一覧は `docs/usage/relays.json`（いまは空）。
- ⏳ 国の引き（手順 3）: 未実装。国の次元を足すときは、公開の形（`v`）を上げる。いまの集計は、中継ごとの合計だけ。
- ⏳ 中継を実際に動かして、`/v1/stats` を Actions から取ること（VPS と push が要る）。

## 結果・注意
- 中継は、計測のために、接続元の IP を一瞬だけメモリに持つ。保存しない。
- 20 件未満の除外は、利用者が少ない間は、ほとんどの国が表に出ないことを意味する。そのときは、中継ごとの合計だけを見る。
