# 0022. AI に環境の情報を渡し、設定で許可したコマンドだけを使わせる

- 状態: Accepted（ユーザーが仕様に同意、2026-11-27）。ブリッジに実装済み（2026-11-28。端末からの実機の確認待ち）
- 日付: 2026-11-27

## 背景
手書きで「今は?」と聞いても、AI は答えられなかった。理由は 2 つ。①システムプロンプトに、日時も、自分が利用者の PC で動いていることも書かれていない。②ブリッジは Claude Code を `--tools ""`（道具をすべて無効）で起動しているので、`date` も打てない。②は、手書きの内容がそのまま AI に渡るため、書かれた文章にコマンドの実行を指示されても、何も起きないようにした、安全のための設計（ADR 0005）。
利用者の考え: AI が PC のコマンドを使えれば、Mac・Windows のローカルのシステムとつながり、使える幅が広がる。ただし、**シェルにペンで触れられるのと同じ危なさ**なので、**本人が、設定で明示的にオンにしたときだけ**許可する。

## 決定
1. **環境の情報**（既定でオン。設定 `ai.environment` で切れる）: 現在の日時（ISO 8601 とタイムゾーン名）と OS の種類（linux・macos・windows）を、システムプロンプトに入れる。**ホスト名・ユーザー名・パス・IP は渡さない。** 道具は使わないので、危険は増えない。
2. **道具の許可**（既定はオフ）: 設定 `ai.tools.allow` に、Claude Code の許可規則の形（例 `Bash(date:*)`）を 1 つずつ書く。**1 つ以上あるときだけ**、`--tools Bash --allowedTools <規則…>` で起動する。許可リストにないコマンドは、実行されない（実機で確認: 2026-11-27、Claude Code 2.1.319。`date` だけが動き、`ls` は動かなかった）。
3. **「すべて許可」は作らない。** `Bash`、`Bash(*)`、`*`、空の規則は、起動時に拒否する。
4. **設定を変えられるのは PC だけ**（`config.json` と、Bridge App の画面）。端末（ノート）や中継から、許可を変えるメッセージは**作らない**。手書きの内容や通信から、シェルの許可を勝手にオンにされないため。変更は、ブリッジの再起動で効く。
5. **設定の誤りは、起動を止めて知らせる**（規則の形が不正、Windows で許可リストがある、など）。黙ってオフにはしない（オフになったと気づかない）、黙って通しもしない。
6. **記録:** 実行を頼まれたコマンドと結果（先頭の一部）を、ブリッジのログと会話の履歴に残す。道具が有効なとき、システムプロンプトに「道具を使ったら、答えの中で、何を使ったか一言添える」と書く。
7. **打ち切り:** 全体の時間切れ（30 秒）と取消で、AI の起動したコマンドごと止める（プロセスグループを終わらせる）。コマンドの実行中は、無応答の判定（10 秒）の対象にしない。

## 影響
- 許可リストのコマンドは、**利用者の権限で実行される。** サンドボックスはない。許可する型は、利用者が責任を持つ。設定の説明に、この点と、読み取りだけのコマンドから始めること、を書く。
- 手書きの文章（ほかの文書の写しを含む）が AI を誘導しても、許可リストの外は動かない。リストの中のコマンドの引数は、AI が決める（例: `Bash(cat:*)` を許すと、任意のファイルが読める）。**引数まで絞れる型を勧める**（例: `Bash(date)`）。
- Windows は、PowerShell と Git Bash の違いがあり、許可規則の書き方が変わる。**最初の版は Linux と macOS だけ**。Windows で許可リストがあれば、起動を拒否して理由を出す。
- プロバイダの境界（ADR 0015）: 道具の許可は、Claude Code のプロバイダの設定。ほかの AI には適用しない。

## 検討した別案
- **すべて許可の切り替え:** 手軽だが、危険が大きすぎる。使い方が見えるまで作らない。
- **端末の画面で許可:** 手書きの内容や通信から、許可を変えられる経路ができる。却下。
- **MCP サーバー経由で、許可した道具だけを渡す:** 構想として別に設計する（ブリッジを MCP のサーバーにする）。この ADR の範囲外。

## 実装での確認（2026-11-28）
実際の `claude` で確かめた: Claude Code は、読み取り専用のコマンド（`ls` など）を、**作業フォルダの中なら許可リストに無くても自動で通す**。ブリッジの作業フォルダは空の一時フォルダなので、見えるものはない。フォルダの外の読み取り（`cat /etc/hostname`）、書き込み（`touch`）、通信（`curl`）、複合コマンドは、許可リストに無ければ断られる。許可の型を `Bash(cat:*)` のように広げると、フォルダの外の読み取りも通ることがある。型は狭く書く。
