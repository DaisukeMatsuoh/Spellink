# 特許・知財の扱い方（このリポジトリのルール）

このフォルダには「どう調べ、どう記録するか」だけを置く。**個別特許の分析は `private/` に置き、git に入れない**（`.gitignore` 済み）。

## なぜ分析を公開リポジトリに入れないのか
- 米国では、特許を**知った上で**侵害すると「故意侵害」として損害賠償が最大 3 倍になり得る。
  「この特許と自分たちの製品はここが同じ/違う」というエンジニアのメモは、後で不利な証拠として使われることがある。
- 侵害かどうかの判断（FTO）は弁理士・弁護士の仕事で、依頼すれば秘匿特権（米国）で守られる形で残せる。
- そのため、公開してよいのは「どのデータベースを、いつ、どんな検索式で調べたか」までにする。

## 記録の残し方
| 種類 | 置き場所 | 公開 |
|---|---|---|
| 検索の記録（日付・DB・検索式・件数） | `private/search-log-*.json` | しない（必要なら要約だけ公開可） |
| 文献ごとのメモ（書誌・請求項の要約） | `private/YYYY-MM-DD-*.md` | しない |
| 弁理士の見解 | 弁理士とのやり取りに残す（リポジトリに置かない） | しない |
| 設計上のルール（例:「記号を書いたら回答で置き換える UI は作らない」） | 必要なら ADR に「理由: 知財上の確認待ち」とだけ書く | する |

## 自分たちの発明について
- このリポジトリを公開（push）すると、そこに書かれたアイデアは**公知**になる。
  - 良い面: 他社がそのアイデアを後から特許にすることを防げる（防衛的公開）。日付の証拠として GitHub の履歴が使える。
  - 注意: 自分で特許を取りたい場合、公開してしまうと新規性を失う。
    日本は「新規性喪失の例外」（公開から 1 年以内に、所定の手続きをして出願）、米国は 1 年のグレースピリオドがあるが、他国では救済されないことが多い。
- 特許を取りたいアイデアがあるなら、**push する前に**弁理士に相談する。
