# Spellink の経緯（2026-10-30 〜 2026-11-08）

人間と別のエージェントが、**何を・なぜ・どの順で作ったか**を、1 本で追えるようにしたもの。いまの状態と次の作業は `README.md`。日付ごとの細かい記録は `log/`（追記専用）。ここは、まとめ直した読み物で、必要に応じて書き直してよい。

## 1. 何を作っているか
Supernote（e-ink 手帳）のノートで、手書きをラッソで囲むと、その文字を AI に聞き、**回答を手書きの筆跡として**ページに書き戻す（「魔法の紙」）。
- 利用者は Supernote のプラグインを入れ、**自分のパソコンで「ブリッジ」を動かす**。ブリッジが、公式の Claude Code（サブスクリプション。API キーは使わない）に聞く。
- ユーザー（開発者本人）はコードを書かない。実装はエージェントが行い、説明は日本語。

## 2. 構成
```
Supernote のプラグイン（React Native）
   │  端末内で手書きを文字にする（OCR）
   │  wss（Cloudflare のトンネル、またはリレー、または LAN）  ← Noise で端末とブリッジの間を暗号化
   ▼
ブリッジ（Go。利用者のパソコン） ── `claude -p`（公式 CLI、ツール無効、空のフォルダ）
   │  回答の文字を、単線フォント（KanjiVG など）から筆跡のストロークに変換
   ▼
プラグインが、行ごとにページへ挿入（ページが足りなければ新しいページを挿入）
```
- `plugin/`（RN。`npm run build` → `build/outputs/Spellink.snplg`）、`bridge/`（Go。`internal/` の `ink`・`server`・`claude`・`history`・`config`・`securechan`・`relay`・`lantls`・`probe`）。
- 設定と会話の記憶は、**ブリッジの機械**に保存（端末には保存手段がない）。
- 開発機: ROCK 5B+（aarch64、Linux）。ツールチェーンは `~/.local/go`。

## 3. 時系列
### フェーズ 1: 調査と設計（10-30 〜 10-31）
- 公式ドキュメント全ページ、`sn-plugin-lib` のソース、先行プラグインを調査（`docs/notes/research/`）。
- 認証の制約を確認: API キーは使わず、サブスクリプションを使いたい。規約上、プラグインにログインを持たせられない → **ブリッジ方式**（ADR 0005）。ブリッジは Node で試作 → **Go に移植**（ADR 0008。単一バイナリ、メモリ約 17MB）。
- 筆跡は、KanjiVG（CC BY-SA）と Hershey から作った単線グリフ（ADR 0003）。長い回答は字数を合わせ、溢れたら次ページへ（ADR 0009）。
- 名前は **Spellink**（10-31 決定）。特許は調査のみ（非公開、`docs/notes/ip/private/`）。弁理士への相談は当面しない。

### フェーズ 2: 実機で動かす（11-01）
- Nomad で、診断画面から、ストローク挿入・新ページ・通信を確認。**平文の ws:// は PluginHost が禁止**、`.local` も引けない → **公的 CA の wss:// が必須**（ADR 0007）。
- Cloudflare のクイックトンネルで、端末からの質問 → 手書き回答まで、初めて成功。Noise による暗号化、リレー（ADR 0010）、LAN 直結（ADR 0011）を実装（後の 2 つは端末での確認が残っている）。
- ユーザーの実機フィードバックを、次々に反映: 英数字の縮小、字間のスライダー、傾き（エージェントごとの書き癖）、15 ストロークずつ書く、待機中の波線アニメ（のちに既定オフ）。

### フェーズ 3: 実機で見つかった不具合と、場当たりをやめる方針（11-01 〜 11-02）
- `strokes: null` でのクラッシュ、波線の消し残し・ユーザーの字を消す、ページ送りで直前のページが空になる（`saveCurrentNote` を呼ばずにファイル系 API を呼んでいた）、別のドキュメントへの書き込み、など。
- ユーザーの方針: **確実な ID で識別する。再試行や推測で帳尻を合わせない**。波線は「印（`userData`）を持つ要素だけ消す」に単純化。
- 回答中に NOTE アプリが固まる件: **フライトレコーダー**（全 SDK 呼び出しの記録をブリッジへ送る）を作って証拠を取る方針に。原因は今も未特定。

### フェーズ 4: ドメインと名前付きトンネル（11-03 〜 11-07）
- ドメイン `spellink.uk`（Cloudflare Registrar）、トンネル `bridge.spellink.uk` → `localhost:8765`（Service は **HTTP**。HTTPS にすると 502）。cloudflared は systemd のシステムサービス（トークンは `/etc/cloudflared/token`）。
- 名前の再検討（`spellink.com` が取得済み）: dancink など。決定していない。

### フェーズ 5: 会話の記憶と、切断への耐性（11-07）
- 同じノートの続きの質問が前を踏まえる（ADR 0012、ノート単位、ブリッジに保存。ユーザー「完璧」）。
- 回答中に `closed (1006)` で止まった → ブリッジが送信失敗を記録していなかったことが判明 → **回答を接続から切り離し、番号つきフレームで再開**（ADR 0013）。

### フェーズ 6: ポリシーと「表」（11-07 〜 11-08）
- ユーザー（組み込みの経験者）の指摘: **戻り値は必ず確認する／全ケースを洗い出す／状態遷移表を先に書く／インターフェースは必ず検証する**。ADR 0014 と `CLAUDE.md` に明文化。
- `docs/spec/` に、状態遷移表（縦=状態、横=イベント、セル=処理と遷移先）とインターフェース台帳を作成。そこから多数の穴を修正: SDK の `result: false` を無視していた、ページ挿入後のページ数を確認していない、ブリッジからのフレームの検証がない、無音の時間切れがない、など。
- **表をコードにした**: 表の文書が元データ → `npm run spec` → 生成された表 → 状態機械。端末の質問の流れ、波線、ページ追加・書き込み、ブリッジの run の 4 つ。テストが、文書とコードの一致・全マスの動作・表の形を守る。
- 無応答の検出を、**プロセスの活動とモデルの活動を見分ける**形に（Claude Code の出力イベントで確認）。思考中は切らず、止まったときだけ 10 秒で切る。
- 空き領域の確認（ページ全体の読み取り）は、重くなりうるので**設定（既定オフ）**に。

## 5. 教訓（同じ失敗をしないために）
- **テストの件数だけでなく、スイートの数を見る。** スイートが落ちると件数が減る（70 件が 53 件に減ったのに「合格」と報告した）。
- **本番の入口からテストする。** ラッソの流れ（`run()`）が選択範囲を渡しておらず、空き領域の確認が実際には動いていなかった。テストが診断の経路だけを通っていた。
- **テストが本当に不具合を捕まえるか、壊して確かめる**（変異テスト）。今回の表のテストも、1 マスを壊して落ちることを確認している。
- ログに「done」とあっても、届いた証拠ではない（送信の失敗を記録していなかった）。**証拠を取る仕組みを先に入れる**。
- 表を後回しにすると、シナリオごとの処理が散らばる。**表が元データなら、直しはマスの書き換え**で済む（ユーザーの指摘で、順序を逆にして正した）。
- `jest.spyOn` は同じ関数に対して同じ spy を返す。`mockImplementationOnce` の積み残しと呼び出し回数は、テスト間で引き継がれる。
- シェルの heredoc でバッククォートがエスケープされる、Python の `re.sub` が置換文字列の `\x` を解釈する、など、ファイルを生成するときの落とし穴に注意。
- 開発機の `~/.claude/settings.json` に、caveman のプロキシ（`ANTHROPIC_BASE_URL`）がある。**Claude Code の Remote Control は、これが原因で使えない**（公式の API でないため）。
