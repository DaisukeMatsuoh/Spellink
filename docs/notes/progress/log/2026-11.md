## 2026-11-21（続き）ブリッジと中継を Rust に移植（ADR 0018）

## 2026-11-21（続き）直結・運営の入口の実装（ADR 0017・0019）
- ユーザーの決定: 同じドメイン `spellink.uk`、名前サービス自身が DNS（NS の委任。**DNS 用のトークンなし**）、Cloudflare Tunnel をやめて VPS（Kagoya の固定 IP）で中継が自分で TLS、scratch のコンテナ、Let's Encrypt が先で Google は後。暗号は ring から **aws-lc-rs** に変更（保守の活発さ。ring は 2025-03 が最後のリリース）。
- 先に書いた表: `docs/spec/lan-cert.md`（登録 4×7、証明書 7×10。生成器で Rust の表に。全マス）、台帳 I28〜I34。表を実装に落とす途中で、**Valid × CertExpires は到達できない**（更新の期限が必ず先）と分かり、C7 を消して表を直した。
- 実装: `namesproto`（Ed25519 の identity、署名つき要求）、`names/{store,dns,api}`（記録・権威 DNS・API）、`tlsserve`（証明書を差し替えられる TLS の受け口。握手と HTTP ヘッダの時間切れ、同時数の上限）、`acme`（instant-acme、DNS-01、証明書の検証・保存）、`lan/`（2 つの状態機械の実行部、名前サービスの HTTP クライアント）、`edge`（中継・名前サービスが TLS で出る）、`names` コマンド、`relay --tls-domain`。ブリッジは `lan.enabled` のとき 8766 で待ち受ける。
- 見つけて直した: **ring を外すと ureq の HTTPS が全部落ちる**（暗号の部品の未指定。`build-glyphs` のダウンロードも）→ `util::install_crypto`（テストあり）。`--flag` が次の `--flag` を値として飲み込む（`relay --trust-proxy --listen …`。Go 版の移植時の持ち越し）。不安定なテスト 3 つ（Nagle の中央値→最速、`names` の UDP の再送、`ETXTBSY`、400 ms の固定待ち→起動を見てから）。極端な負荷（25 プロセス×64 スレッド）でも通る。
- 変異チェック: names（リプレイ・ID のハッシュ・時刻・ゾーンの末尾・拡張ラベル・保存）、lan（古い結果の破棄・CA の時刻・期限切れの証明書を出さない・アドレス変更・失敗の表）。生き残ったのは、等価な 1 つ（登録の再試行の期限の掃除。動作が同じ）。
- 文書: ADR 0017 を書き直し（Accepted）、0019 を追加、0011 は Superseded、0010・0018 に追記。構成図（`architecture.md`）、運営の手順（`relay-operations.md`）、`docs/notes/research/README.md`（各メモの状態と結論）、`deploy/vps/compose.yaml`、`bridge/Dockerfile.edge`。

## 2026-11-22: ペアリングの導入を、設定なしで通るようにした
- 原因: `device add` は、基になるプラグインのパッケージを `config.json` の `pairing.pluginPackage` から読んでいた。設定が要ることは、手順書にしかなかった。
- 直したこと: パッケージをブリッジに埋め込む（`bridge/build.rs`、環境変数 `SPELLINK_BASE_PACKAGE`）。設定の `pluginPackage` があれば、そちらを優先する。`scripts/build-with-plugin.sh` が、クリーンなプラグイン（`plugin/scripts/clean-package.sh`）を作って埋め込む。
- **見つけた危険（のちに根本から消した）**: プラグインのビルドは `plugin/src/bridges.local.json`（住所とトークン）を束に埋めていた。ペアリング（ADR 0016）の前の名残で、いまは要らない。ユーザーの指摘で、**埋め込みの道そのものを削除**した（`bridgeConfig.ts` の `baked`、`prepare-local-config.js`、`.gitignore` の行、ローカルのファイル）。source の値は `'baked'` から `'none'` に。後で消す作りをやめ、パッケージは住所もトークンも持たない。
- リリースのワークフローに、クリーンなパッケージを作る job を足した（**まだ動かしていない**）。
- `device add` の案内を書き直した。利用者向けの `docs/guides/install-guide.md` を新設。
