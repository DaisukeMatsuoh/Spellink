# 回答がページに収まらない問題と「大きな紙」の検討（2026-10-31）

## Supernote の制約か？
はい。NOTE のページは**端末のページサイズで固定**（Nomad 1404×1872、Manta 1920×2560 px）で、
無限キャンバスや縦長ページは NOTE にない。プラグイン API もページ単位（ページの挿入・削除・移動、レイヤー、リンク）。
したがって「大きな模造紙を自由にズームして動き回る」編集体験は、**プラグインの範囲を超える**。

## プラグインでできること・できないこと
| 案 | 内容 | プラグインで | e-ink との相性 |
|---|---|---|---|
| A. 長さを空きに合わせる | 選択範囲の下に入る文字数を計算し、その字数で答えるよう Claude に頼む | ○（**実装済み**） | ◎ 描画が増えない |
| B. 次のページに続ける | 下端に達したら直後に新しいページを挿入し、そのページに切り替えて続きを書く | ○（**実装済み・実機未確認**） | ◎ ページめくりは純正操作で速い |
| C. 回答ページ＋リンク | 選択範囲の横に短い要約と「回答へ」のリンクを書き、全文は別ページ（または回答専用ノート）に書く | ○（API: `insertTextLink` / `setLassoStrokeLink` / `createNote`） | ○ |
| D. ステッカー化 | 回答をステッカーにして、ユーザーが縮小・移動できるようにする | △（`convertElement2Sticker` などはあるが、ステッカーが拡大縮小できるかは要確認） | ○ |
| E. 俯瞰ビュー（閲覧のみ） | 複数ページを縮小画像（`generateNotePng`）にしてタイル状に並べ、拡大縮小して眺める。タップでそのページへ移動 | ○（プラグインの全画面 UI として） | ○ 静止画なので軽い。ただし描き込みはできない |
| F. 本物の無限キャンバス | 拡大縮小・パンしながら手書きもできる大きな紙 | ×（プラグインでは純正の手書きエンジンを使えない。自前アプリ＝サイドロード APK になり、NOTE との統合とペン遅延の良さを失う） | △ e-ink でのパンは遅い |

## 折り返し幅
回答は常に**ページ幅（左右の余白を除く）で折り返す**。横スクロールは発生しない。
座標はノートファイルのページサイズ基準なので、Nomad では Nomad の幅、Manta では Manta の幅で折り返す。
（Manta で作ったノートを Nomad で開いた場合はファイル側のサイズが使われる。）

## 今回の実装（ADR 0009）
- ブリッジ: 1 ページ目に入る字数を見積もり（`ink.Capacity`）、システムプロンプトで「◯字以内」と指示。
  それでも溢れたら、最大 3 ページ（元のページ＋2 ページ）まで続ける。各行に `page`（元のページからの相対番号）を付けて送る。
- プラグイン: `page` が増えたら `insertNotePage` で直後にページを挿入（テンプレートは元ページと同じ。カスタムテンプレートは白紙）→ `jumpToPage` でそのページを表示 → 書き込み。
  既存の次ページには書かない（ユーザーの書き込みを壊さないため）。

## 今後の候補
- C（回答ページ＋リンク）を設定で選べるようにする: 「その場に書く / 続きは次ページ / 要約＋リンク」
- E（俯瞰ビュー）は「模造紙」体験に一番近い現実解。会話（質問と回答のページ群）を地図のように眺められる
- F は Ratta が NOTE に無限キャンバスを入れるか、SDK が独自キャンバス上の手書きを許すまで保留
