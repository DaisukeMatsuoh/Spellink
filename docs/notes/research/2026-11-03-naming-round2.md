## 所感（エージェント）
- **`.com` まで空いているのは dancink / conjurink / burstink / spoutink**。
- **dancink**: 体験（回答が筆跡として踊りながら現れる）に一番合い、短い。難点: 綴りが「dan-cink」にも見え、読みが揺れる（「ダンシンク」と読まれやすい）。「dancing」の言い換えとは分かりやすい。
- **conjurink**: spell と同じ「呪文」軸で、現行の世界観を保てる。長く、発音しにくい。
- **burstink / spoutink**: 「迸る」は表せるが、インクが噴き出す印象が強く、静かな手帳には合わない。
- 一語の造語は、ブランドとして取りやすい反面、検索で見つけてもらいにくい。
- ユーザー向けの説明は「Claude」「Supernote」を名前に入れず、本文で「Claude Code で動く」「Supernote 向け」と書く（`2026-10-31-naming.md` の商標の注意）。

## 推奨
**dancink**（.com・.app・.ink がすべて空き）。読みの揺れは、ロゴや説明で「dancing ink」と添えれば吸収できる。
ただし決めるのはユーザー。決定前に、J-PlatPat と USPTO の商標検索（簡易）をしておくと安全。

## 別案: 名前とドメインを切り離す
製品名は Spellink のまま、**トンネル用の安いドメインだけ別に取る**ことも可能（`docs/guides/cloudflare-tunnel-setup.md` の B 案）。
トンネル用ホスト名は利用者に見えない（プラグイン内部の URL）ので、製品名と一致させる必要はない。
公開用サイトが要るときに、改めて名前に合うドメインを取ればよい。

## 改名するときの作業範囲（決定後にエージェントが一括で行う）
- 変えてよい: プラグイン表示名・`pluginKey`・`app.json`、ブリッジのバイナリ名と設定ディレクトリ（`~/.config/spellink-bridge/` → 移行処理が要る）、Noise のプロローグ・PSK 導出の文字列（`spellink/2`、`spellink-psk-v1:`）、波線の印（`spellink-wave:`）、Go モジュールパス（GitHub のリポジトリ名変更後）、docs、systemd/launchd の名前。
- **変えてはいけない**: `plugin/PluginConfig.json` の `pluginID`。
- 注意: Noise の文字列を変えると旧版と通信できなくなる（公開前なので影響は開発機と端末のみ）。
- push はしていない（公開前）ので、今が一番安い。
