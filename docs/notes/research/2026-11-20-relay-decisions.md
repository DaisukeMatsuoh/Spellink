# 中継（リレー）の運営: 何が分かっていなくて、何を決めるか

2026-11-20。前提: ADR 0010（中継は、暗号化されたフレームを流すだけ）、`2026-11-01-relay-hosting.md`（置き場所の比較）、ADR 0016（端末ごとの鍵。中継の部屋は、使える秘密ごと）。
中継は**実装済み・実機での確認は済み**（トンネル経由）。足りないのは運営の判断。

## 1. 先に答える: 「拒否」と「ブリッジ不在」を分けられるか
- **セキュリティ上は、分けても悪くない。** 部屋の ID は鍵のハッシュ（128 ビット）で、推測できない。分かるのは「この部屋の持ち主は失効した」だけで、すでに持っている人（その端末）にしか意味がない。
- **制約は技術的な作りの問題**。今は、失効すると秘密と一緒に部屋の登録をやめるので、中継は「部屋がない」としか言えない。分けるには、ブリッジが**失効した端末の部屋を登録し続けて、そこに来た接続を「拒否」で返す**必要がある（部屋の ID＝ハッシュは台帳に残す。鍵は消す）。台帳に項目が増え、部屋の数が（16 台まで）少し増える。
- 結論: **文言を 1 つにする（採用。「登録されたブリッジが見つかりません。…動いているか確かめ、動いているのに見つからなければ、ペアリングが解除されたかもしれません」）**。直結・トンネルの住所では、今までどおり「拒否」を見分けて専用の文言を出す。中継でも見分ける実装は、必要になったとき（利用者が中継だけで使い、失効が頻繁になったとき）に足す。

## 1.5 Anthropic の規約: 確認した内容（2026-11-20。<https://code.claude.com/docs/en/legal-and-compliance>）
- **OAuth（サブスクリプションのログイン）は、購入者本人の「通常の利用」のためのもの。** 「Advertised usage limits for Pro, Max, and Ultra plans assume ordinary, individual usage of Claude Code and the Agent SDK.」
- **製品やサービスを作る開発者は、API キーを使う**。Claude.ai のログインを自分のアプリに組み込むこと、**利用者に代わって Free・Pro・Max・Ultra の資格情報で要求を中継すること**、Claude.ai の資格情報やセッショントークンを**集める・保存する・仲介する**ことは、許されない。
- **許されていること**: 「Nor does it prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription」（利用者が、**改変されていない Claude Code** に、**自分のサブスクリプション**でサインインすること）。
- **Claude Code を製品に組み込む場合の条件**: バイナリを改変しない。ログインの方法を外したり制限したりしない。利用者の代わりに利用料を払う・転売する・仲介することはしない（各利用者が自分の資格情報で認証する）。
- **名前**: 「Claude Code」「Anthropic」の名前やロゴを、製品名・ロゴに含めない。Anthropic が作った・承認した・提携していると思わせない。**平文で、正確に、「Claude Code を動かします」と書くのは、よい。**
- 報道（二次情報）: 2026-02 に、サブスクリプションのトークンを第三者の製品で使うことを禁じる明確化があり、その後 `claude -p` と Agent SDK の利用は、サブスクリプションの本体とは**別枠の、月ごとの「Agent SDK クレジット」**から引かれる扱いに変わった（2026-06-15 から、とのこと）。**公式の最新の扱いは未確認**（`support.claude.com` の記事で確認する）。**Spellink はブリッジから `claude -p` を呼ぶので、この別枠の上限が、利用者の体験（回数の上限）に効く可能性がある。**
- **Spellink が守ること**（設計と文書に反映する）: ①公式の `claude` を**そのまま**起動する（改変しない。ログイン情報に触れない）②**利用者自身のパソコン・自身のログイン**③第三者にサービスとして提供しない（初回の起動の同意で、「このパソコンのログインは自分のもの。自分だけが使う。端末の利用者も自分」と同意してもらう。`docs/legal/terms-of-service-draft.md` の 2）④台帳は 16 台まで（1 人の持ち物の範囲）⑤名前は「Spellink」。「Claude Code」は、事実を述べる文の中だけ。

## 2. 分かっていないこと（調べる・決める人つき）
| # | 不明・未決 | 内容 | 誰が |
|---|---|---|---|
| 1 | **Anthropic の規約** | **公式ページで確認した（下の「Anthropic の規約: 確認した内容」）。** 結論: Spellink の形（利用者自身のパソコンで、改変していない公式の Claude Code を、利用者自身のログインで動かす）は、公式の記述が**許している形**に当たる、と読める。条件は、利用者が本人であること・第三者へのサービスにしないこと。**ただし、私は法律の専門家ではなく、規約は頻繁に変わる**（2026 年に何度も変わった）。公開の前と、変更があるたびに、公式ページを確認する。必要なら Anthropic に書面で問い合わせる | ユーザー（最終の判断。問い合わせるか） |
| 2 | 運営するか | 公式の中継を運営するか、利用者が自前でトンネルを用意する形だけにするか | ユーザー |
| 3 | どこで動かすか | フェーズ 1: 開発機＋Cloudflare Tunnel（0 円。自宅の回線・停電に左右される）。公開前に、小さな VPS か Fly.io（月 5 USD 前後）へ。中継は状態を持たないので、移転は DNS の向け先を変えるだけ | ユーザー（費用）／エージェント（手順書・systemd ユニット） |
| 4 | 費用と資金 | ドメイン（`spellink.uk` は取得済み）、サーバー、通信量。見積もり: 回答 1 回 数十〜数百 KB。1 人が 1 日 100 回で約 10 MB。1,000 人で月 300 GB 程度。寄付（Buy Me a Coffee など）で賄うか、有料にするか | ユーザー |
| 5 | 見えるもの・ログ・プライバシー | 中継に見えるのは、部屋の ID・接続元の IP・時刻・通信量。内容（質問・回答・鍵）は見えない（Noise）。**IP をログに残さない／短期だけ残す**を決め、**プライバシーポリシー**に書く（日本語・英語） | ユーザー（方針）／エージェント（文面の草案） |
| 6 | 可用性の約束 | 「ベストエフォート、保証なし」と明記するか。止まったときの代わり（自前トンネル・LAN 直結）と、障害の知らせの場所 | ユーザー |
| 7 | 乱用への備え | 今は、接続元ごとの回数制限（端末 60／ブリッジ 12／受け口 120 回・分）、部屋数の上限（10,000）、部屋あたり 4 セッション。誰でも部屋を作れるので、**帯域の乱用**（鍵を知らなくても、接続だけはできる）の上限（部屋ごとの帯域・アイドル切断）を足すか | エージェント（実装）／ユーザー（上限の値） |
| 8 | 運営者の持続性 | 個人で運営する場合、止まったときの利用者への影響。**中継の URL は設定で変えられる**ので、自前運営へ移れる。運営をやめるときの告知の仕方を決める | ユーザー |
| 9 | 公開の時期 | 中継を、先に少人数（身近な利用者）だけで試すか | ユーザー |

## 3. 推奨（たたき台）
1. #1 の規約の確認を**最初に**行う（結果しだいで、他の判断が変わる）。
2. 運営する（#2）。ただし**ベストエフォート・無保証**、**IP は保存しない**、**内容は見えない**を明記（#5・#6）。
3. 公開前に VPS へ（#3）。それまでは開発機＋Cloudflare Tunnel（`spellink.uk` のサブドメイン）。
4. 帯域の上限と、アイドル切断を足す（#7。エージェントが実装）。
5. 自前運営の手順書（同じバイナリ）を `docs/guides/` に置き、運営をやめても使い続けられる形にする（#8）。

## 4. エージェントができること（ユーザーの判断を待たずに進められる）
- 帯域の上限・アイドル切断の実装とテスト／systemd ユニットと運営手順書／プライバシーポリシーの草案（日英）／失効した端末の部屋を「拒否」で返す実装（必要になったとき）。
