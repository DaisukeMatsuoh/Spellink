## 残り（公開の前に判断が要る）
可用性の弱点。個人の寄付運営の規模なら当面は許容できるが、広く公開する前に直す。
- **名前サービス: 登録のたびに、全記録を書き出し、fsync まで、DNS と同じロックの中で行う。** 登録が洪水になると DNS の応答が止まり、ACME の検証と家の名前引きが失敗する。直し方: ロックの外で、スナップショットを書く（書く順序は専用のロックで守る）。
- **TLS の入口**: 接続ごとの本体の読み取りに期限がなく（4 KiB を 1 バイトずつ送られる）、接続元ごとの同時接続の上限もない（8192 を埋められる）。中継の制御接続は、クライアントの ping で 15 分の無通信の期限が延び続ける。直し方: 本体の期限、接続元ごとの上限、サーバー側の ping。
- **Let's Encrypt の枠**: 任意の ID が、`<id>.lan.spellink.uk` の証明書を無料で注文できる。大量に作ると、`spellink.uk` の枠（週 50 件）を使い切られ、中継と名前サービス自身の**新規**発行も止まる（更新は別枠）。直し方: `lan.` を別の登録ドメインにする、ID の作成を絞る。**ADR 0017 の判断に関わる。**
- DNS の接続元ごとの制限（100 回/秒）は、大きな公開リゾルバや、なりすまされた送信元に不利。
- `--trust-proxy` は、最初の `X-Forwarded-For` を信じる。Cloudflare の後ろ専用と書く（現在の構成は使わない）。
- コンテナ: `cpus`・`ulimits`・ヘルスチェックなし。ベースイメージは固定していない。
- ブリッジ: 管理 API と画面が、LAN からも届く（トークン必須。接続元の IP が loopback かは見ていない）。管理トークンが URL の `#` に載り、ブラウザの履歴に残る。既存の `admin.token` の権限は確認していない。
- 端末: K が MyStyle の名前に平文で載る（同じ端末の別アプリが読める）。端末の設計上の限界として文書に書く。
- 文字データの生成: ダウンロードにハッシュがなく、展開後の大きさに上限がない（`build-glyphs` の実行時だけ）。
- 1 つの `Status.error` を、登録と証明書の 2 つの機械が上書きし合う（表示だけ）。
