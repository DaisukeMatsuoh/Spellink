# 端末: 質問から回答まで（`plugin/src/askFlow.ts`、`askController.ts`）

対象: ラッソのボタンを押してから、回答を書き終える（または止まる）まで。1 回の質問が 1 つの `AskFlow`。
状態は質問ごと。終了状態（S7〜S9）から、次のボタン押下で、新しい `AskFlow` が S1 から始まる。

## 状態
| 記号 | 状態 | 意味 |
|---|---|---|
| S0 | IDLE | 質問なし |
| S1 | PERM | 権限の確認中 |
| S2 | RECOG | ノートの場所・ラッソの範囲を読み、端末内の文字認識中 |
| S3 | PREP | ページの読み取り、波線、ブリッジへの接続、（必要なら）新しいページへの移動 |
| S4 | STREAM | `ask` を送り、`line` を受けて書いている |
| S5 | RESUME | 完了前に接続が切れ、再接続して続きを頼んでいる（ADR 0013） |
| S6 | DRAIN | `done` を受け取った。書き込みの列に残った行を書き切るところ |
| S7 | OK | 完了 |
| S8 | FAIL | 失敗（理由を利用者に伝える） |
| S9 | CANC | 利用者が取り消した |

## イベント
| 記号 | イベント | 例 |
|---|---|---|
| E1 | PRESS | ラッソのボタンを（もう一度）押した |
| E2 | CANCEL | 進捗パネルの取消・閉じる |
| E3 | DENIED | 権限が拒否された |
| E4 | NOTEXT | 認識結果が空または null（楽譜・絵など） |
| E5 | REFUSED | SDK の呼び出しが失敗、または `result: false`（拒否） |
| E6 | SILENT | ノートアプリが時間内に答えない |
| E7 | MOVED | いま開いているノートが、質問したノートと違う |
| E8 | NOBRIDGE | どのブリッジにも接続できない |
| E9 | LINE | 正常な `line` フレーム |
| E10 | BAD | 異常なフレーム（値が不正、ページが範囲外、型が不明） |
| E11 | DONE | `done` フレーム |
| E12 | ERR | 回答を終わらせる `error` フレーム |
| E13 | CLOSE | 接続が切れた（`done` の前） |
| E14 | RESUME-OK | 再接続できて `resume` を送った |
| E15 | RESUME-NG | 再接続できない、またはブリッジがその回答を覚えていない（`unknown_ask`） |
| E16 | QUIET | 接続は生きているが、ブリッジから一定時間フレームが来ない |
| E17 | LATE | 終わった（`done` 後・終了後）あとに届く切断やフレーム |
| E18 | LIFE | プラグインのホストのライフサイクル通知（停止・再開・破棄） |

## 注
- a: 取り消す対象がない／終わっている。
- b: 質問が動いていないので、そのイベントを生む処理がない。
- c: すでに動いている質問がある。二重に始めない（`askController.startAsk`）。**利用者への表示は出さない**（⚠ 提案: 無反応に見えるので、短い通知を検討 ❓）。
- d: その状態では、そのイベントを生む処理が動いていない。
- e: 接続がまだない、またはまだ `ask` を送っていないので、フレームは来ない。
- f: 認識の間にノートが変わっても、読み取りだけなので害はない。以降の書き込み前に `ensureOpen` が検出する（A12）。
- g: ページの読み取り・走査の失敗は A6（続行）。新しいページへの移動に失敗したら A4。
- h: 接続は S3 で済んでいる。
- i: 接続がないので受け取れない。
- j: 接続成立後、`ask` を送る前に切れた場合の処理が決まっていない。現状は、`send` の例外で S8 になる（推定、テストなし）。仕様は A9（再接続して `ask` を出し直す）か A4 か ❓。
- k: 再接続は S5 の間だけ。
- l: 完了（または終了）した後に無音を検出しても意味がない。タイマーは終了時に止める。
- m: **穴**: `line.page` が範囲外（`MAX_EXTRA_PAGES` 超え）でもページを挿入し続ける。`strokes` の中身（`p` と `w` の長さの不一致、NaN、巨大な本数）を検証していない。不明な型は黙って無視している。A7 は、これらを検査して S8 へ。
- 時間切れの値: 通常 15 秒、保存・読み取り・ページ挿入・認識は 60 秒（`sdk.ts`）。
- E16 の既定値案: 最初のフレームまで 120 秒、以降のフレーム間 60 秒 ❓。ブリッジ側にも Claude への時間切れがない（bridge-run.md）。

3. S1 / E6: 権限確認の SDK 呼び出し（`PluginManager.hasPermission` / `requestPermission`）も共通の処理を通す。
4. E13 @ S3: 接続成立後の切断の仕様決定と実装。
5. E18: ホストのライフサイクルの意味を実機で調べ、処理を決める。
6. E1: 二重押下の記録と、利用者への表示の判断。
