# 端末: 質問から回答まで（`plugin/src/askFlow.ts`、`askController.ts`）

対象: ラッソのボタン（「AIに聞く」）を押してから、回答を書き終える（または止まる）まで。1 回の質問が 1 つの `AskFlow`。
状態は質問ごと。終了状態（S7〜S9）から、次のボタン押下で、新しい `AskFlow` が S1 から始まる。

実装の方針（ADR 0014）: 表を**コードの表そのもの**にする。`Record<状態, Record<イベント, セル>>` とし、セルは「処理 + 次の状態」の組。型で全マスを強制し、範囲外の状態・イベントは失敗として止め、全マスを順に走らせるテストを書く。

## 状態
| 記号 | 状態 | 意味 |
|---|---|---|
| S0 | IDLE | 質問なし |
| S1 | PERM | 権限の確認中 |
| S2 | RECOG | ノートの場所・ラッソの範囲を読み、端末内の文字認識中 |
| S3 | PREP | ページの読み取り、波線、ブリッジへの接続、（必要なら）新しいページへの移動。前回の波線の消し残しの確認（wave.md） |
| S4 | STREAM | `ask` を送り、`line` を受けて書いている |
| S5 | RESUME(n) | 完了前に接続が切れ、再接続を試している。**n = 試行回数（0〜3）**。画面には「再接続中 (n/3)」 |
| S6 | DRAIN | `done` を受け取った。書き込みの列に残った行を書き切るところ |
| S7 | OK | 完了 |
| S8 | FAIL | 失敗（理由を利用者に伝える） |
| S9 | CANC | 利用者が取り消した |

## イベント
| 記号 | イベント | 例 |
|---|---|---|
| E1 | PRESS | 処理中に、ラッソの「AIに聞く」をもう一度選んだ（連打、または回答中の再操作） |
| E2 | CANCEL | 進捗パネルの取消・閉じる |
| E3 | DENIED | 権限が拒否された |
| E4 | NOTEXT | 認識結果が空または null（楽譜・絵など） |
| E5 | REFUSED | SDK の呼び出しが失敗、または `result: false`（拒否） |
| E6 | SILENT | ノートアプリが時間内に答えない |
| E7 | MOVED | いま開いているノートが、質問したノートと違う |
| E8 | NOBRIDGE | どのブリッジにも接続できない |
| E9 | LINE | 正常な `line` フレーム |
| E10 | BAD | 異常なフレーム（値が不正、ページが範囲外、型が不明） |
| E11 | DONE | `done` フレーム |
| E12 | ERR | 回答を終わらせる `error` フレーム（AI の失敗・時間切れを含む） |
| E13 | CLOSE | 接続が切れた（`done` の前） |
| E14 | RESUME-OK | 再接続できて `resume` を送った |
| E15 | RESUME-NG | 再接続できない、またはブリッジがその回答を覚えていない（`unknown_ask`） |
| E16 | QUIET | 接続は開いているが、ブリッジからの通信（フレームも生存通知も）が一定時間まったく来ない = 接続が死んでいる |
| E17 | LATE | 終わった（`done` 後・終了後）あとに届く切断やフレーム |
| E18 | LIFE | プラグインのホストのライフサイクル通知（停止・再開・破棄） |
| E19 | SCREEN | 設定画面・診断画面を開いた |

## 注
- a: 取り消す対象がない／終わっている。
- b: 質問が動いていないので、そのイベントを生む処理がない。
- c（廃止）: 二重押下は A2 で反応する（決定 2026-11-07）。
- d: その状態では、そのイベントを生む処理が動いていない。
- e: 接続がまだない、またはまだ `ask` を送っていないので、フレームは来ない。
- f: 認識の間にノートが変わっても、読み取りだけなので害はない。以降の書き込み前に `ensureOpen` が検出する（A12）。
- g: ページの読み取り・走査の失敗は A6（続行）。新しいページへの移動に失敗したら A4。
- h: 接続は S3 で済んでいる。
- j: 接続成立後、`ask` を送る前に切れた場合は A9b（決定: 再接続の方針に合わせる）。
- k: 再接続は S5 の間だけ。
- l: 完了（または終了）した後に無音を検出しても意味がない。タイマーは終了時に止める。
- m: 設定・診断を開く操作は、回答に影響しない。回答は続き、画面は要求どおり開く（`askController` の `show` は画面を切り替えるだけ）。パネルの取消ボタンだけが取消（E2）。
- o: 対応済み（2026-11-07）。以前の穴: `line.page` が範囲外（`MAX_EXTRA_PAGES` 超え）でもページを挿入し続ける。`strokes` の中身（`p` と `w` の長さの不一致、NaN、巨大な本数）を検証していない。不明な型は黙って無視している。
- **別のノートに移ったとき（E7）は、いまのまま止める**（決定 2026-11-07）。回答を保留してブリッジに残し、戻ったときに続きを書く案は、将来の候補として残す（SDK に「ノートが開かれた」イベントがないため、ボタン押下時に、開いているノートを確かめる方式になる）。
- **E16 の考え方**: ここでの無音は、**接続が死んでいるかどうか**だけを見る（ネットワークの問題）。Claude 側が長く考えている場合は、ブリッジが約 5 秒おきに生存通知（`status`）を送るので、無音にならない。**AI が黙っている場合の時間切れは、ブリッジが持つ**（bridge-run.md の R13: 最初の出力まで 30 秒、出力の間 20 秒。`config.json` で変更可）。無音の長さは、生存通知の間隔の数倍（案: 15 秒）⚠ 要確認。
- 時間切れの値: SDK 呼び出しは通常 15 秒、保存・読み取り・ページ挿入・認識は 60 秒（`sdk.ts`）。再接続の確立は 5 秒（`connectFirst`）。
