# ノートアプリ（ホスト）への依頼の列（`plugin/src/sdk.ts` の `native`・`pump`）

**状態: 確認済み・実装済み（2026-11-24。利用者の了承を得て実装）。** 実機で「答えの来ない依頼 1 本で、以後すべての依頼が、プラグインを終了するまで止まる」ことが分かったため、この表を先に書く（これまで、列には表がなく、ADR 0014 の文章とコードのコメントだけだった。表がなかったので、「答えが来ない依頼」の行き先が決まっていなかった）。

## 何が起きたか（実機、2026-11-24）
1. 診断の「確認」で `getCurrentFilePath` に答えが来なかった。
2. 現在のコードは、依頼の席を、**ホストが答えるまで**返さない（呼んだ側が時間切れで諦めても）。答えが来なければ、席は戻らない。
3. 後ろの依頼は、送られないまま時間切れになる。**画面を閉じて入り直しても、JS の実行環境は残っているので、席は戻らない**（プラグインの終了、端末の再起動まで）。
4. `hasPermission`（ノートに触らない、PluginManager の依頼）まで、同じ列で止まった。

## 依頼の種類（この表が、コードの分類表になる）
| 種類 | 依頼 | 並べ方 | 呼んだ側が諦めたあと |
|---|---|---|---|
| **管理** | `PluginManager` の `hasPermission`・`requestPermission`・`getDeviceType`・`getPluginDirPath`・`showPluginView` | **ノートの列に並ばない**（ノートに触らない）。管理どうしは、同時に最大 4 | 席を、すぐ返す |
| **閉じる** | `closePluginView` | 列にも管理の席にも並ばず、すぐ送る（I19） | 席なし |
| **読む（状態）** | `getCurrentFilePath`・`getPenInfo`・`canHandwrite`・`getCurrentPageNum`・`getNoteTotalPageNum`・`getPageSize`・`getLassoRect`・`getLassoElements`・`getElements`・`recognizeElements` | **ノートを変える依頼と同時には走らない**（状態に依存するため）。読む依頼どうしは 1 本ずつ | **席を、すぐ返す**（読むだけなので、遅れて動いても、ノートは壊れない。遅れて来た答えは捨てる） |
| **変える** | `saveCurrentNote`・`insertNotePage`・`jumpToPage`・`createElement`・`insertText`・`insertPageElements`・`deletePageElements`・`setLassoBoxState` | **1 本ずつ**。前の依頼が**決着するまで**（答えが来るまで）次を送らない | **席は、答えが来るまで返さない**（ホストの中で動いているかもしれない。重ねて送るとノートが壊れうる） |
| **要素の読み取り** | 手元の要素の点列などのアクセサ | 最大 8 同時。変える依頼とは同時に走らない | 席を、すぐ返す |

## 状態
| 状態 | 意味 |
|---|---|
| IDLE | 走っている依頼がない |
| READ | 「読む（状態）」が 1 本走っている |
| SHARED(n) | 「要素の読み取り」が n 本走っている（n ≤ 8） |
| MUT | 「変える」が 1 本走っている（呼んだ側は待っている） |
| MUT-LOST | 「変える」を、呼んだ側が諦めた。ホストはまだ答えていない（**ここに留まる間、「変える」「読む」「要素の読み取り」は送らない**） |

（「管理」と「閉じる」は、この列の外にあるので、状態を持たない。）

## イベント
| 記号 | イベント |
|---|---|
| mut | 「変える」の依頼が来る |
| read | 「読む（状態）」の依頼が来る |
| sh | 「要素の読み取り」の依頼が来る |
| ans | 走っている依頼に、答えが来る |
| to-w | 呼んだ側が、**順番を待っている間に**諦める（時間切れ） |
| to-r | 呼んだ側が、**走っている間に**諦める（時間切れ） |
| late | 諦めたあとの依頼に、答えが来る |

## 表（縦=状態、横=イベント。セル=処理 → 次の状態）
`wait` = 列の先頭から順に待たせる（追い越さない）。`drop` = 待っていた依頼を、送らずに捨てる。時間切れの待ち時間は、列に並んでいる時間も含む（積み上がらない）。

| 状態＼イベント | mut | read | sh | ans | to-w | to-r | late |
|---|---|---|---|---|---|---|---|
| **IDLE** | 送る → MUT | 送る → READ | 送る → SHARED(1) | 起こらない（走っている依頼がない） | 起こらない（待ちがなければ、すぐ送る） | 起こらない | 捨てる（諦めた読みの答え。何もしない）→ IDLE |
| **READ** | wait（READ が終わるまで） | wait（1 本ずつ） | wait | 次の待ちを送る → IDLE（待ちがあれば、先頭の種類へ） | drop（呼んだ側に SIL）→ READ | **席を返す**（呼んだ側に SIL）、先頭の待ちを送る → IDLE または次の状態 | 捨てる → 現状のまま |
| **SHARED(n)** | wait（n 本が終わるまで） | wait | n < 8 なら送る → SHARED(n+1)、n = 8 なら wait | n-1 → SHARED(n-1)、0 になれば待ちを送る | drop（SIL）→ 現状のまま | **席を返す**（SIL）→ SHARED(n-1)、0 になれば待ちを送る | 捨てる → 現状のまま |
| **MUT** | wait | wait | wait | 次の待ちを送る → IDLE（待ちがあれば、先頭の種類へ） | drop（SIL）→ MUT | **席は返さない**（SIL）→ **MUT-LOST** | 起こらない（まだ諦めていない。答えは ans） |
| **MUT-LOST** | wait（呼んだ側は、時間切れまで待つ。**送らない**） | wait（同上） | wait（同上） | 起こらない（諦めたあとの答えは late） | drop（SIL）→ MUT-LOST | 起こらない（走っている依頼がない） | **席を返す**、待ちを送る → IDLE（または次の状態） |

## この表で決まること
1. **「読む」ための依頼が答えなくても、列は詰まらない**（呼んだ側が諦めた時点で、席が戻る）。今回の事故（`getCurrentFilePath`）は、この行で防がれる。
2. **「変える」が答えないときだけ、列は、答えが来るまで止まる**（安全のため。ノートが壊れうるので、重ねて送らない）。待たされた依頼は、時間切れで SIL になり、利用者には「ノートアプリが応答しません」と出る。**遅れて答えが来れば、自動で再開する。**
3. **管理と閉じるは、ノートの列の影響を受けない。** 権限の確認、画面を開く・閉じる、診断の「送る」が、ノートの依頼で止まらない。
4. 「読む」を諦めたあとで、遅れて動いた「読む」が、ノートの状態を変えることはない（読むだけ）。**ただし、`recognizeElements` は、ホストの中で時間のかかる処理なので、遅れて動いても、次の依頼と競合しない**ことを、実機で確かめる（未確認）。

## テスト（各マスに 1 つ）
`__tests__/sdkSafety.test.ts` の「the line of requests to the note app」に、上の表の各セルに対応するテストがある（ホストが答えない・遅れて答える・諦める、を、偽のホストで作る）。「管理は、ノートの列が詰まっていても動く」「読むが答えなくても、次の読むが動く」「変えるが答えないときは、次の変えるが**送られない**」「遅れて答えが来たら再開する」は、必須。

## 実装
`plugin/src/sdk.ts`: `kindOf`（名前から種類）、`native`・`pump`・`release`（席の返し方）。名前の分類表は `MANAGER_CALLS`・`READ_CALLS`（ここに無い名前は「変える」）。新しい SDK の呼び出しを足すときは、この表と、分類表を直す。
