# インターフェース台帳（受け渡しの境界ごとの検証）

モジュール間・関数間・プロセス間の受け渡しは、不具合が最も入りやすい場所。**信頼境界（相手のコードや外の世界から来る値）では、受け取る側が必ず検証する。** 型だけでは、実行時に届く値は保証されない（JSON、SDK の戻り値、ファイル、子プロセスの出力）。

## 検証の方針（ADR 0014）
1. 受け取った値は、**使う前に**、型・範囲・長さ・個数・欠け・NaN/無限大を確かめる。
2. 不正だったときの処理を**決めて書く**（中断、既定値で続行、捨てて記録のどれか）。黙って通さない。
3. 「相手が正しく作るはず」を理由に省かない。バージョン違い、バグ、改ざん、壊れたファイルは必ず起きる。
4. 内部の関数どうし（同じ信頼の範囲、型で保証されるもの）では、重複して検証しない。ただし前提を関数の説明に書く。
