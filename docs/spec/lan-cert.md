# 家の中の直結: 名前の登録と証明書の取得（ブリッジ。`bridge/src/lan/`）

対象: ADR 0017。ブリッジが、自分の名前 `<id>.lan.spellink.uk` を名前サービスに登録し、Let's Encrypt から自分の証明書を取り、8766 で `wss://` を待ち受けるまでの寿命。
**この文書の 2 つの表が、コードの表の元データ**（`npm run spec`。生成物は `bridge/src/lan/reg_table.rs` と `bridge/src/lan/cert_table.rs`）。書式は ask-flow.md と同じ（`—` 起こりえない、`×` 起きるが無視する）。

2 つの機械に分ける理由: 「名前と IP を登録しているか」と「有効な証明書を持っているか」は、別々のタイミングで変わる。IP が変わっても証明書は取り直さない（証明書は名前に対するもの。IP は DNS の A レコードだけの話）。合わせると、状態が掛け算で増える。

**中継は、この機械の成否に関わらず使える。** 直結は近道であって、使える条件ではない。取れなくても利用者にエラーは出さない（状態は `status` と設定画面に「直結は準備中」と出すだけ）。

## 不変条件
- L1: 証明書の秘密鍵は、ブリッジの外に出ない（名前サービスにも、Let's Encrypt にも渡らない。渡るのは CSR だけ）。
- L2: 待ち受けに使う証明書は、**有効期間内のものだけ**。期限が切れたものは捨て、待ち受けは握手を拒否する（古い証明書を黙って出さない）。
- L3: 名前サービスに載せる IP は、**プライベートの IPv4 だけ**（公開 DNS に載る）。
- L4: 注文（ACME の order）は、同時に 1 つだけ。古い試みの遅れた結果は、**試みの番号**で見分けて捨てる（時間や回数では見分けない）。
- L5: 認証用の TXT は、注文が終わったら（成功も失敗も）消す。消せなくても、名前サービスが期限（10 分）で消す。
- L6: 再試行の間隔は、CA が示した時刻（上限のエラーの文にある `retry after …`）に従う。示されない失敗は、下の固定の表に従う（1 分・5 分・30 分・2 時間・以後 6 時間。成功で戻る）。理由: Let's Encrypt は、同じ名前の検証の失敗を 1 時間に 5 回までに制限している。場当たりの再試行はしない。
- L7: 取得したのち、証明書と鍵は、一時ファイルに書いて名前を変える（0600）。読み戻して確かめてから、待ち受けに使う。
- L8: 取得の失敗や待ちは、ブリッジの起動・通常の質問・中継を止めない。
- L9: 名前サービスは、**直近 7 日に初めて注文を始める ID を 45 まで**に絞る（ADR 0017 の追記。Let's Encrypt の週 50 枚のうち 5 枚は、運営の中継・名前サービスの新規発行のために空ける）。断るときは、いつ空くかの時刻を返す。ブリッジは、これを `RateLimited`（CA の上限と同じ扱い）として受け、その時刻まで待つ。**更新と、同じ ID の再試行は数えない**（その ID が初めて注文を始めた時刻だけを数える）。運営が指定した ID（`--infra-ids`）と、名前サービス自身は数えない。

## 登録: 状態
| 状態 | 意味 |
|---|---|
| Off | 無効（設定で `lan.enabled` が false） |
| Registering | 登録の試みの最中（名前サービスに、自分の ID・公開鍵・IP を署名つきで送っている） |
| Registered | 登録済み。名前サービスは、いまの IP を持っている |
| RegisterWait | 登録に失敗した。再試行の時刻を待っている |

## 登録: イベント
| イベント | 意味 |
|---|---|
| Enable | 有効になった（起動時に設定が有効、または設定の変更） |
| Disable | 無効になった（設定の変更、またはブリッジの停止） |
| AddressChanges | LAN のプライベート IPv4 が、登録した値と違う（または、なかったものが見つかった） |
| RegisterOk | 試みが成功した（試みの番号が現在のもの） |
| RegisterFails | 試みが失敗した（アドレスが見つからない、ネットワーク、名前サービスの拒否、時間切れ） |
| RetryDue | 再試行の時刻が来た |
| RegistrationLost | 名前サービスが、この ID を知らないと答えた（名前サービスのデータが消えた） |

## 登録: 処理（Action）
| 処理 | 内容 | 現状 | テスト |
|---|---|---|---|
| N1 | 新しい試みの番号を付け、LAN のプライベート IPv4 を探して、登録を送る（見つからなければ、その試みは `RegisterFails`）。待っていたタイマーは止める | ❌ | `lan::tests` |
| N2 | 試みとタイマーを止める（遅れて届く結果は、番号で捨てられる） | ❌ | 同上 |
| N3 | 失敗を記録し、再試行のタイマーを置く（L6） | ❌ | 同上 |
| N4 | 成功を記録し、証明書の機械に `RegistrationReady` を渡す | ❌ | 同上 |
| N5 | 動いている試みを番号ごと捨て、新しい IP で N1 をやり直す | ❌ | 同上 |

## 登録: 状態遷移表
| 状態＼イベント | Enable | Disable | AddressChanges | RegisterOk | RegisterFails | RetryDue | RegistrationLost |
|---|---|---|---|---|---|---|---|
| **Off** | N1→Registering | ×a | —b | —c | —c | —d | —b |
| **Registering** | ×a | N2→Off | N5 | N4→Registered | N3→RegisterWait | —d | ×e |
| **Registered** | ×a | N2→Off | N1→Registering | —c | —c | —d | N1→Registering |
| **RegisterWait** | ×a | N2→Off | N1→Registering | —c | —c | N1→Registering | ×e |

## 登録: 注
- a: すでに有効（または無効）。何もしない。
- b: 無効のあいだは、IP の監視も、名前サービスとのやりとりもしない。
- c: 動いている試みがないので、結果は届かない（届いても、番号が違う遅れた結果は、機械の外で捨てる）。
- d: 再試行のタイマーは RegisterWait だけで動く。
- e: 登録の試みの最中または待ちで、すでに登録をやり直すところ。

## 証明書: 状態
| 状態 | 意味 |
|---|---|
| Off | 無効 |
| AwaitRegistration | 有効。証明書がない。登録が済むのを待っている（注文には、名前サービスが ID を知っている必要がある） |
| Ordering | 証明書がない。注文の最中（Let's Encrypt に注文し、名前サービスに TXT を置いてもらう） |
| OrderWait | 証明書がない。注文に失敗した（または上限）。再試行の時刻を待っている |
| Valid | 有効な証明書を持ち、待ち受けている |
| Renewing | 有効な証明書で待ち受けながら、更新の注文の最中 |
| RenewWait | 有効な証明書で待ち受けながら、更新に失敗した。再試行の時刻を待っている |

## 証明書: イベント
| イベント | 意味 |
|---|---|
| Enable | 有効になった。保存された、有効な証明書はない |
| EnableWithCert | 有効になった。保存された証明書が有効期間内にある（再起動後など） |
| Disable | 無効になった（設定の変更、ブリッジの停止） |
| RegistrationReady | 登録の機械が Registered になった |
| Issued | 注文が成功した（試みの番号が現在のもの。証明書は検証済み） |
| RateLimited | CA が上限に達したと答えた（再試行の時刻つき） |
| OrderFails | 注文が、上限以外の理由で失敗した（ネットワーク、検証の失敗、名前サービスの拒否、時間切れ、CA のエラー） |
| RetryDue | 再試行の時刻が来た |
| RenewDue | 更新の時期（残り 30 日、または有効期間の 3 分の 1 のうち短いほう） |
| CertExpires | 証明書の有効期間が切れた |

## 証明書: 処理（Action）
| 処理 | 内容 | 現状 | テスト |
|---|---|---|---|
| C0 | 状態を「登録待ち」と記録する（画面には「直結は準備中」） | ❌ | `lan::tests` |
| C1 | 新しい試みの番号を付け、注文を始める。タイマーは止める（L4） | ❌ | 同上 |
| C2 | 試みとタイマーを止め、待ち受けをやめる（保存された証明書は残す） | ❌ | 同上 |
| C3 | 注文の結果が届いた時点で、証明書と鍵は検証・保存・待ち受けへの入れ替えまで済んでいる（失敗なら、そこで `OrderFails`。L7）。ここでは `RenewDue`（残り 30 日、または有効期間の 3 分の 1 のうち短いほう）と `CertExpires` の期限を置き、失敗の回数を戻す | ❌ | 同上 |
| C4 | 失敗を記録し、再試行のタイマーを置く（L6。上限なら CA の時刻） | ❌ | 同上 |
| C5 | 保存された証明書で待ち受け、`RenewDue` と `CertExpires` のタイマーを置く | ❌ | 同上 |
| C6 | 期限切れの証明書を待ち受けから外す（L2）。動いている注文とタイマーは、そのまま | ❌ | 同上 |

| **Renewing** | C4→RenewWait | C4→RenewWait | —d | —d | C6→Ordering |

## 証明書: 注
- a: すでに有効（または無効）。何もしない。
- b: 無効のあいだは、登録の機械も無効なので、`RegistrationReady` は作られない。
- c: 動いている注文がないので、結果は届かない（番号が違う遅れた結果は、機械の外で捨てる）。
- d: そのタイマーは、その状態では動いていない（状態が変わると、そのタイマーは消える）。証明書がない状態では、更新も期限切れもない。
- e: 登録がやり直され（IP の変更など）、また済んだ。注文は ID だけで進む（IP は使わない）ので、そのまま続ける。
- 起動の順序: ブリッジは、証明書の機械を先に有効にし、そのあと登録の機械を有効にする（`RegistrationReady` を取りこぼさないため）。
- f: Valid では、更新の期限は終わりより必ず先で、同じ見回りでも `RenewDue` が先に処理されるので、Valid が `CertExpires` に出会うことはない（スリープ明けで両方が一度に来ても、Renewing に移ってから `CertExpires`、つまり C6）。
- 登録が `RegistrationLost` になっても、証明書の機械は動かさない（登録がやり直されるあいだも、有効な証明書で待ち受けられる）。

## 名前サービス側の受け取り（状態機械にしない理由）
名前サービスの記録（ID → 公開鍵・IP・TXT）は、「ある」「ない」だけで、遷移の順序で振る舞いが変わる状態を持たない。各要求は、独立に**検証して、書くか断る**。その検証は `interfaces.md` の I28〜I31 に書く。

週の枠（L9）も、ここで数える。記録に「初めて注文を始めた時刻」（`firstOrder`。なければ 0）を持ち、TXT の設定（`set`）が初めて来たときにだけ決める。数えるのは、直近 7 日にその時刻がある ID（運営が指定した ID と、名前サービス自身を除く）。45 に達していたら、その ID の最初の `set` は `429 lan_quota` と、いつ空くかの時刻（`retryAfter`。unix 秒。いちばん古い時刻 + 7 日）を返し、nonce は使い切らない。すでに時刻のある ID の `set`・`clear` は、数えず、断らない。
